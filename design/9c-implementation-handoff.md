## 本轮交付

本轮用三个并行 Agent 分别推进菜单、弹层与下拉按钮，`Decorator` / `Viewbox`，以及 `Popup` / `ToolTip`；主工作区整合了 Fluent 样式、Control Catalog、预览脚本和文档。

## 关键实现位置

- [CSS 动画采样](../src/AwAUI.Css/Animation/CssAnimator.cs)：样式无关变化触发重算时，按当前时钟采样旧动画值，避免结束后的旧 transform 被当作新 transition 的起点。
- [动画悬停回归用例](../tests/AwAUI.UI.UnitTests/AnimationHoverTests.cs)：检查 Sheet 滑入后 hover 重算不移动面板。
- [FocusScope 生命周期](../src/AwAUI.Controls/Primitives/Focus/FocusScopeComponent.cs)：关闭动画期间可先退出焦点栈、到实际卸载再恢复焦点；动画期间重开可撤销待恢复。
- [菜单](../src/AwAUI.Controls/Controls/MenuFlyout.cs)：自身管理焦点会话、方向键、Home/End、TypeAhead、焦点恢复与关闭；菜单项用 `IsEnabled`、`TextValue`、`OnClick`、`Command` 和 `CommandParameter`。
- [Popup](../src/AwAUI.Controls/Controls/Popup.cs)：用 `Anchor` (`Ref<Element>`) 与 `IsOpen` / `IsOpenChanged`；默认 Escape 与外部指针关闭。默认 AutoFocus 开启，不困住焦点。
- [ToolTip](../src/AwAUI.Controls/Controls/ToolTip.cs)：要求一个直接内建目标，不额外包装 target 的尺寸或 Tab 停靠；默认 ShowDelay 500 ms / CloseDelay 150 ms。
- [Slider 共用行为](../src/AwAUI.Controls/Primitives/Slider/SliderBehavior.cs)：Controls 和 Shadcn 共享值缩放、ARIA、键盘与指针捕获。
- [布局后组件重建](../src/AwAUI.UI/UIRoot.cs)：`InvalidateFromLayout()` 仅用于挂接标准管线布局回调内的测量驱动重建；在有限轮数内、绘制前完成。
- [虚拟化宿主](../src/AwAUI.Controls/Primitives/Virtualization/VirtualizerHost.cs)：`Virtualizer` + `ScrollController` 的共用胶水；`Begin`/`Track` 记录本次实现的行，布局完成后测量变高行并请求重建。`ItemsRepeater`、`ListBox`（`IsVirtualized`）与 `TreeView`（展平为带 `aria-level` 的行）共用它。
- [TreeView 懒加载](../src/AwAUI.Controls/Controls/TreeView.cs)：`LoadChildren` 在项首次展开（或构建时已展开）时调用，`_lazyChildren` 按键缓存，`RefreshChildren` 清除缓存并重载；完成回调经宿主调度器封送到 UI 线程（无调度器时调用方需自行在 UI 线程完成）。
- [文本编辑](../src/AwAUI.UI/Input/TextEditHistory.cs)：`ReplaceValueRange` 记录编辑后的值与选区；插入 / 删除按插入点相邻合并，光标移动、点击、换行与失焦分组，程序改写值清空历史；Ctrl/⌘+Z 撤销、加 Shift 重做（Windows / Linux 另有 Ctrl+Y）。
- [插入点闪烁](../src/AwAUI.UI/Input/RenderPipeline.Input.cs)：绘制输入框时按光标版本重新开始可见阶段，`UIClock` 定时器到期后切换 `CaretVisible` 并请求重绘；无时钟时不闪烁。周期取 `Input.CaretBlinkInterval`，未设置时用进程级的 `RenderPipeline.CaretBlinkInterval`。
- [系统外观偏好](../src/MacOS/AwAUI.MacOS/MacAppearancePreference.cs)：`NSApplicationDidChangeEffectiveAppearanceNotification` → `IAppearancePreference` → `UIHost` → `RenderPipeline.SetPrefersDark`；与 [Reduce Motion](../src/MacOS/AwAUI.MacOS/MacReducedMotionPreference.cs) 同一套 `WindowImpl.GetFeature<T>()` 订阅方式。Windows 侧见 [Win32Preferences](../src/Windows/AwAUI.Win32/Win32Preferences.cs)：注册表 `AppsUseLightTheme` 与 `SPI_GETCLIENTAREAANIMATION`，在 `WM_SETTINGCHANGE` / `WM_THEMECHANGED` 后刷新。Linux 侧见 [X11SettingsPreference](../src/Linux/AwAUI.X11/X11SettingsPreference.cs)：读取 `_XSETTINGS_S0` 选择所有者的 `_XSETTINGS_SETTINGS` 属性，`Net/ThemeName` 含 “dark” 为深色、`Gtk/EnableAnimations` 为 0 为减少动效，属性变化后重读；字节流解析在 [XSettingsParser](../src/Linux/AwAUI.X11/Settings/XSettingsParser.cs)，是不依赖 Xlib 的纯逻辑。
- [边框盒绘制](../src/AwAUI.UI/Rendering/BoxPainter.cs)：`PaintBorder` 的分边颜色分支用 `CornerSplit` 取外圆角弧心作为梯形角顶点（圆角内外弧同心，内边距盒的直角角点会把弧外楔形漏给背景），并沿各边方向外扩一个设备像素让相邻梯形在接缝处重叠；回归测试见 [BorderCornerTests](../tests/AwAUI.UI.UnitTests/BorderCornerTests.cs)（1px / 半透明 / 1px 1px 2px / 4x 四种场景）。
- [系统字体](../src/AwAUI.Text/Fonts/SystemFonts.cs)：`DirectorySystemFontProvider` 递归枚举各系统字体目录（macOS `/System/Library/Fonts`、Windows `%WINDIR%\Fonts`、Linux `/usr/share/fonts` 等），第一次用到时才访问磁盘；`GetFallbackFamilies` 按 UAX #24 文字与 BCP 47 语言给出简体 / 繁体 / 日文 / 韩文 / 阿拉伯文等具体族名。`FontCollection.SystemFonts`（[FontCollection](../src/AwAUI.Text/Fonts/FontCollection.cs)）先按文件名归一化匹配（`msyh.ttc` → Microsoft YaHei 等缩写表），未命中再建一次全量族名索引；回退缓存键包含语言环境。
- [语言环境](../src/AwAUI.UI/Rendering/TextParagraph.cs)：`TextStyleMapper` 把 `CultureInfo.CurrentUICulture`（BCP 47）写入 `TextStyle.Locale` 并纳入样式缓存键；`OpenTypeShaper` 据此选择 `locl` / 语言系统，`TextLayout.ChooseFace` 把同一个语言传给字体回退。与 Avalonia 一致，内建控件没有独立的 Language 属性，元素的 `lang` 属性目前只参与 `:lang()` 选择器。
- [缺字通知](../src/AwAUI.Text/Fonts/FontManager.cs)：`FontManager.MissingGlyphs` 在回退链（含系统字体）走完仍无字型时触发，参数含码点与语言环境；注册新字体或设置 `SystemFonts` 会清空回退缓存。
- [目录级与项目级导入](../src/Markup/AwAUI.Markup.Generator/GlobalImports.cs)：`_Imports.awaui` 解析目录导入；[ComponentResolver](../src/Markup/AwAUI.Markup.Generator/ComponentResolver.cs) 从编译中的 `global using` 收集项目级导入并加入标签候选；MSBuild 属性 `AwAUIMarkupNamespaces`（分号或逗号分隔）提供项目自己的组件命名空间，排在全局 using 之后、框架内置命名空间之前；`AwAUIMarkupBuiltInNamespaces` 替换框架内置的两项（设为 `none` 禁用），两者都在 `buildTransitive/AwAUI.Markup.props` 中声明为 `CompilerVisibleProperty`。

`Popup` does not create its own trigger: the application owns the anchor and must update `IsOpen` when `IsOpenChanged` fires. `ToolTip` accepts only one built-in button, input, div, span, text, or image node directly; attach a Tooltip to a custom Controls component only after verifying it produces one of those built-in element nodes. Its content is descriptive, not a nested interactive surface.

`Viewbox` accepts a CSS-sized viewport or an auto-sized axis: in `Uniform` mode it writes the natural content aspect ratio as `aspect-ratio`, so an auto height is the scaled height and the parent sees the real desired size; both axes definite keeps the min-scale fit. Use `Stretch="None"` for natural size. The first mount and later viewport changes use the layout-completed path without an entry transition.

## Remaining Limits

- `MenuFlyout` remains the flat action menu; `Menu` / `MenuItem` / `ContextMenu` cover menubars, submenus and target wrapping. Native (OS) popup menus are not implemented.
- `Popup` is an explicit nonmodal anchored surface. More modal dialog behavior belongs to DialogHost / Shadcn Dialog.
- `TransitioningContentControl` now keeps the outgoing content mounted for `TransitionDuration` (default 150 ms) as an absolutely positioned, `pointer-events: none`, `aria-hidden`, `inert` layer that fades out while the new content enters; without a clock, a zero duration or `IsTransitionEnabled = false` the swap is immediate. `Element.IsInert` makes the whole subtree of an element carrying the `inert` attribute unfocusable and skips it in Tab order, so no element in the outgoing layer can be reached by keyboard during the exit. Focus inside the old content moves to the new content root.
- `ItemsRepeater` virtualizes along either axis (`Orientation`, default vertical). Vertically, `Lanes = 1` with a fixed `ItemHeight` is O(1) and `ItemHeight = null` measures variable-height rows after layout (realized rows only, with scroll anchoring); `Lanes > 1` lays the realized items out as a vertically scrolling grid (`RowGap` / `ColumnGap`, row height = tallest item in the row). Horizontally, `ItemWidth` (or `null` with `EstimatedItemWidth`) sets the main-axis size and `Lanes` stacks rows vertically; `ColumnGap` becomes the main-axis gap and `RowGap` the lane gap. `ListBox` and `TreeView` opt in with `IsVirtualized` plus `ItemHeight` (fixed) or `ItemHeight = null` (measured); a virtualized `TreeView` renders flat rows with `aria-level` instead of nested groups. `TreeView` can load children on demand through `LoadChildren` (cached per key, `RefreshChildren` to invalidate); loaded children are not written back into the immutable `TreeViewItem` snapshot, and an in-flight load still completes after a refresh. `ItemsControl` opts in with the same `IsVirtualized` / `ItemHeight` / `EstimatedItemHeight` / `Overscan` properties (inherited by `ListBox`) plus `Orientation` / `ItemWidth` / `EstimatedItemWidth` for horizontal scrolling; it ignores `ItemsPanel` while virtualized and realizes rows in a `position:relative` extent with `data-index` / `aria-posinset` / `aria-setsize`. Virtualization requires a constrained height in vertical mode and a constrained width in horizontal mode. Horizontal virtualization positions items with logical `inset-inline-start`, so an RTL container starts at the right edge; `ScrollController.OffsetX` is measured from the inline start (right in RTL) and the physical translation, wheel / touch / keyboard direction, scrollbar thumb and `ScrollIntoView` all follow the container's used `direction`. `TreeView` virtualization remains vertical only.
- `Viewbox` reports the scaled desired size through `aspect-ratio`; it does not reflow the child (the child stays at its natural max-content width).
- `RelativePanel` positions children after layout and writes the child extent back as `min-width` / `min-height` on auto-sized axes, using the panel origin for panel-aligned children so the reported size cannot grow or shrink from round to round. Relations that place a child outside the panel (for example *right of* a right-aligned sibling) overflow as usual.
- `AutoCompleteBox` matches with the default case-insensitive prefix rule or a custom `ItemFilter`, and `ItemsSourceProvider` fetches suggestions asynchronously as the user types (results replace the static items, the token is canceled when a newer request supersedes it, stale responses are dropped by generation, failures call `ItemsSourceError`, `IsBusy` drives `aria-busy`, and `Refresh` re-runs the current query). `ItemsSourceProviderDebounce` (default zero) delays provider queries on the UI clock so rapid typing issues one request for the final text, `Refresh` bypasses the delay, and returning to text whose results are already loaded cancels the pending query; without a clock the request runs immediately. Provider mode ignores `ItemsSource` and `SelectedIndex` indexes the current result list, and without a dispatcher (headless) completion runs on the thread that completes the provider task.
- `NumericUpDown` formats and parses with `Culture` (default `CultureInfo.CurrentCulture`), including culture group separators; the ARIA `aria-value*` attributes stay invariant so assistive technology can parse them.
- `MaskedTextBox` is backed by `Primitives.MaskedTextProvider`: the common placeholder subset (`0 9 # L ? A a & C`, `\` escape, literal characters), the `>` / `<` case directives and `|` optional position, culture-sensitive `.` `,` `:` `/` `$` mask characters (`Culture`, default `CurrentCulture`), `MaskCompleted` / `MaskFull`, masked caret / selection (`SelectionStart` / `SelectionEnd` / `SelectionLength` / `CaretIndex`) and `Set` / `Replace` / `InsertAt` / `RemoveAt` / `RemoveRange`. `IncludeLiterals` / `IncludePrompt` exist only on the provider; the control always exposes the formatted text with literals and prompt characters. Formatted-index mapping always addresses the full mask layout, and a one-character paste (not driven by Backspace / Delete) falls back to the tracked pre-edit caret when it has to decide which side of a literal to delete.
- macOS Reduce Motion and the system light / dark appearance are connected to `prefers-reduced-motion` / `prefers-color-scheme` through `UIHost`, including live changes. Windows reads `AppsUseLightTheme` (application mode) and the accessibility "Show animations" setting after `WM_SETTINGCHANGE` / `WM_THEMECHANGED` and exposes them through the same `WindowImpl.GetFeature<T>()` path. Linux reads XSETTINGS (`Net/ThemeName`, `Gtk/EnableAnimations`) through the same path; dark detection is the "dark" substring convention because XSETTINGS has no standard colour-scheme key, and selection-owner changes are detected by a throttled re-check on root property events when XFixes is not used. None of the three preference backends has been exercised on a real window on its OS in this environment.
- Shadcn S1 keyboard / pointer / touch acceptance lives in `ShadcnInteractionTests` (button, checkbox, switch, label, tabs, radio group, toggle group, slider, accordion, collapsible, toggle), `ShadcnOverlayTests` (select, dropdown menu, popover, dialog, alert dialog, sheet, tooltip) and `ShadcnSemanticsTests` (card, alert, separator, progress, table, input, textarea, avatar, scroll area, aspect ratio, kbd / skeleton / spinner). `ShadcnGoldenTests` adds light / dark reference images and structural assertions, `ShadcnRtlTests` covers mirrored flex rows, logical inset swapping, text alignment, an asymmetric icon and the sheet side, and `ShadcnSemanticSnapshotTests` snapshots button, checkbox, switch, tabs, select (closed / open), dialog, accordion, table and invalid input. The goldens are AwAUI-rendered references, not official website screenshots; the official-site comparison performed on 2026-11-21 found the live site on the nova style while these goldens track the still-published new-york-v4 registry (see 官网对照 above). RTL now runs through the engine: CSS `direction` is a phase-1 inherited property, the HTML `dir` attribute is a presentational hint, and the used value reaches `LayoutStyle.Direction` (block alignment, flex main axis, grid placement) and `ParagraphDirection` in the text engine (bidi paragraph level, `start` / `end` alignment). The RTL stylesheet therefore no longer mirrors rows, `text-align`, or card footers with explicit `:dir(rtl)` rules. Inline-start / inline-end logical properties (`padding-inline-*`, `margin-inline-*`, `inset-inline-*`, `border-inline-*`) are now cascade-time longhands mapped through the used `direction`: the engine first resolves the direction from `direction` declarations / the `dir` hint, then translates every logical declaration to its physical longhand as it cascades, so physical-vs-logical order, `!important`, `revert` and `var()` substitution all follow normal cascade rules; `getComputedStyle` reads a logical name through the same mapping. `SheetContent` accepts `Side.InlineStart` / `Side.InlineEnd` (classes use `start-0` / `end-0` and `border-s` / `border-e`, and the portal follows the document `direction`), and `Popper` resolves logical sides at the engine entry so middlewares and `data-side` only see physical sides. Inline scroll offsets (`scroll-margin-inline-*` / `scroll-padding-inline-*`) and the four logical corner radii (`border-start-start-radius` ...) are cascade-time longhands too, `DropdownMenuSubContent` and the core `Menu` submenu open on `Side.InlineEnd`, and the menu bar / item keyboard handling reads the content element's used `direction` (ArrowLeft opens a submenu in RTL); `overscroll-behavior-inline` deliberately stays a parse-time alias because the inline axis is x in horizontal writing and does not flip with direction. Icon mirroring stays explicit (`transform: scaleX(-1)` or swapping the icon): CSS transforms are geometric and have no logical form, so the engine does not automatically mirror icons. `writing-mode` (vertical writing) is not implemented, so logical corners only resolve for horizontal-tb; decision D52 records that vertical writing and automatic icon mirroring are out of scope for 1.0.
- Undo / redo is limited to the focused input's own history (no cross-element history). The caret blink interval defaults to the process-wide `RenderPipeline.CaretBlinkInterval` and can be overridden per input with `Input.CaretBlinkInterval` (`TimeSpan.Zero` keeps the caret solid).
- Runtime Tailwind completion is opt-in and Debug-first: `TailwindRuntime.Enabled` defaults to on only in DEBUG builds, the `AwAUITailwindRuntime` generator property is off by default, and the generated `CreateRuntime()` requires the app to reference `AwAUI.Tailwind`. Local `@import`s in the entry stylesheet need an app-supplied `TailwindOptions.Resolver` (the build-time resolver reads AdditionalFiles). Invalid candidates are collected once in `InvalidCandidates`, raise `InvalidCandidate` once per class, and can be forwarded as `AW2001` through the now-public `UIRoot.ReportDiagnostic` (TailwindDemo does this); `TailwindRuntime.Bind(sheet.Update)` wires the current CSS and every `Changed` event to an `AppStyleSheet`; `BindIncremental(sheet.Update)` does the same and also passes the first changed top-level offset (`ChangedFrom` / `LastChangeOffset`), which `AppStyleSheet.Update(string, int)` uses to reuse the parsed prefix rules and diagnostics and reparse only the tail. `UIDevToolsOptions.ClassCandidates` can be wired to `TryAddCandidates` and `ClassCandidatesRemoved` to the new `RemoveCandidates` (a class that disappears from the tree retracts its utility rules; the rule slot stays at its sort position, so re-adding the class restores the exact same text without a recompile). The observer now diffs the whole tree's class set once per dirty frame instead of remembering every class forever, so quiet frames do not call back and a class that returns is reported again; theme variables and `@property` / `@keyframes` are shared output and are not retracted. The composed text is maintained incrementally: a new rule is inserted into the existing `@layer utilities` block at its index, late theme blocks go before the global `@property` / `@keyframes` blocks, and globals are appended; each change still materializes a new complete string for the atomic `Css` swap, but no longer walks and re-emits every rule. Incremental parsing is now implemented as well: `StyleSheet.ParseIncremental` reuses every top-level rule and diagnostic that ends before the changed offset (their absolute ranges stay valid for DevTools), parses only the tail, and falls back to a full parse when the prefix differs, the change lands inside a rule, or the offset is out of range; `AppStyleSheet.Update(string, int)` and `TailwindRuntime.BindIncremental` / `ChangedFrom` connect it. The Tailwind runtime reports the `@layer utilities` block start for rule inserts / removals (the whole block reparses, the baseline prefix is still reused), the old globals position for an appended theme block, and the old end for appended `@property` / `@keyframes`. `Update(string)` remains the full-parse path.
- Scroll positions and physics are double now, but `ScrollController.MaxOffset` / `Offset` / `ContentSize` / `ViewportSize` still expose `Point` / `Size` (one float conversion at the public boundary), and layout content sizes are still capped at 1e7 logical pixels. `VirtualizerHost` clamps through the public float `MaxOffset` while the offset itself flows as double.
- 系统字体是**目录扫描**，不是各平台的原生枚举（DirectWrite / CoreText / fontconfig）：族名按 name 表解析，文件名提示未命中时第一次会建全量索引（Windows 上约数百个文件，一次性耗时）；没有做按需的 cmap-only 探测，也没有字体配置（fontconfig 规则、`@font-face` 的 `unicode-range`）。浏览器 / Headless 仍使用 `SystemFontProvider.Empty` 或应用注册的清单，缺字只触发 `MissingGlyphs`，不会自动下载。`TextInputOptions` 的语言提示在桌面后端是空实现（与 Avalonia 相同）。
- IME 的四个平台修复只做了编译与纯逻辑 / 无头测试；**没有**在真实系统输入法（微软拼音、IBus / Fcitx、macOS 拼音）上运行过，窗口焦点失活、候选窗定位与 X11 非 UTF-8 locale 仍是最需要真机验证的部分。

### 官网对照（2026-11-21，网络可用）

用 Microsoft Edge 无头模式（`--headless=new --window-size=1280,3600`，`prefers-color-scheme` 明 / 暗各一次）抓取 `https://ui.shadcn.com/docs/components/button`（默认 Base UI）、`/docs/components/radix/button`（Radix UI）与 `/docs/components/aria/button`，并用 `https://ui.shadcn.com/r/styles/<style>/<component>.json` 读取官方注册表源码。结论：

- 官网三个标签页现在渲染的是同一套 **nova** 样式组件（注册表 `radix-nova` / `base-nova`），不再是 `new-york-v4`：按钮为 `h-8 rounded-lg`、`hover:bg-primary/80`、`active:not-aria-[haspopup]:translate-y-px`、`group/button`、`has-data-[icon=…]`，`destructive` 变体改为 `bg-destructive/10 text-destructive`（不再是实心红）；输入框为 `h-8 rounded-lg px-2.5`（无 `shadow-xs`）；选择触发器为 `rounded-lg`；卡片为 `rounded-xl ring-1 ring-foreground/10` + `--card-spacing`（不再是 `border + shadow-sm + py-6`）；Dialog 内容为 `rounded-xl ring-1 ring-foreground/10 sm:max-w-sm`；Tabs 列表为 `h-8 rounded-lg`；Badge 为 `rounded-4xl`。
- 本仓库 S1 仍按 **new-york-v4** 注册表实现。逐字核对：`Button.awaui` 的基础类与全部 variant / size 类串和 `new-york-v4/button.json` 完全一致；`Input` / `Checkbox` / `Switch` / `SelectTrigger` / `Card` / `Dialog` 等也是 v4 类串（例如输入 `h-9 rounded-md px-3 shadow-xs`、卡片 `border + shadow-sm`）。
- 渲染实测（官网 light 截图，1x）：nova Default 按钮高约 30–32 px、圆角约 8 px、填充纯黑 `rgb(0,0,0)`；AwAUI v4 Default 按钮高 36 px、圆角 8 px、填充 `#171717`（`new-york-v4` neutral 主题 `--primary: 0 0% 9%`）。高度、破坏性变体和卡片 / 输入框的描边方式因此不同；这不是 AwAUI 的渲染误差，而是两套注册表样式的差异。
- 因此官网像素一致不是 S1 当前可达状态：官网已领先于本仓库采用的注册表。截图与注册表原文保存在临时目录（未入库），可用上面的 URL 与命令复现。若决定跟随官网，应整体迁移到 nova（Button / Input / Select / Dialog / Card / Tabs / Badge 等），并同步重写黄金图、RTL 与语义快照；这是一次独立的样式迁移，不属于 9c 的剩余验证项。
